perf(garden): virtualized month-sectioned flower bed

The garden previously rendered every record as its own motion+SVG node -
a few thousand records would stack thousands of components and tens of
thousands of path nodes, and even flowerOf was recomputed every render.

- virtual scrolling: fixed-height rows (4 cols desktop / 2 mobile),
  only viewport +/- 3 buffer rows render; rows are absolutely positioned
  inside a total-height spacer, scroll listener rAF-throttled, window
  located by binary search over row offsets - render cost is constant
  regardless of record count
- month section headers as rows in the same virtual list (YYYY/M)
- flowerOf mapping memoized in row build (useMemo on records/filter),
  not per render; per-flower framer-motion layout animation removed
  (disastrous under virtualization), entrance fade dropped for plain
  hover states
- inner fixed-height scroll area (62dvh, overscroll-contain) so the
  virtual window works inside the page-level scroll
- data-range honesty: when the in-memory window (MAX_HISTORY=200) is
  smaller than the total count, a caption states the garden shows the
  latest N of M (same semantics as the list view); full data still in
  exports/backups
- i18n x5 for the caption; tsc + 192 tests green
